## Intuition: shape describes a collection of positions

An array shape says how many positions exist along each axis. A scalar has shape (), a vector-shaped array has one axis, a matrix has two, and a batched array adds leading axes. The shape participates in the operation; it is not merely a label attached afterward.

Computational vectorization expresses a collection of operations through array primitives. It does not mean that every array represents a directed displacement in a geometric space. This explorer focuses on index correspondence: for each output position, identify exactly which positions of the two inputs supplied its values.

Values are bounded consecutive integers in row-major order, beginning at the two selected starts. This keeps the hand calculations exact while exposing shape mechanics. Later real floating-point arrays retain their numerical issues even when the shape operation is valid.

## Definition: trailing-axis broadcasting

Align shapes from the last axis. Missing leading axes behave as length one. At each aligned axis, the sizes must be equal, or one must be one. A size-one input axis reuses index zero at every output position on that axis.

The output size at an aligned axis is the shared size when equal, or the other size when one side is one. This distinction matters for empty dimensions: zero with one produces zero length, not length one. Zero with a different nonunit size is incompatible.

This bounded explorer supports at most four axes, sizes 0–4, and at most 64 elements in each input and output. A compatible output beyond that limit is labelled as mathematically compatible but outside the demonstration bound. It is distinct from an incompatible pair.

## Mechanics: indices, operations and reductions

The source-index table shows each output index, its left input index, its right input index, both values and the exact elementwise result. Addition and multiplication operate on those selected elements. They are not matrix multiplication, contraction or dot product.

Reduce a zero-based output axis by summing its actual values and removing that axis from the shape. Negative axis indices count from the end; all reduces every axis to a scalar. An empty sum is zero. Invalid axes remain explicit: a scalar has no explicit axis in this teaching contract, although all can reduce it to itself.

Shape syntax and allocation bounds are validated before any output construction. Valid inputs with incompatible shapes remain available to inspect; the operation has no output values, rather than a silently repaired shape.

## Derivation: the index projection

Let the output multi-index be $\mathbf i$. For each input, define a projection that drops missing leading axes and replaces every size-one axis index by zero. The elementwise addition is then

$$C_{\mathbf i}=A_{\pi_A(\mathbf i)}+B_{\pi_B(\mathbf i)}.$$

For shapes (2,3) and (3,), the right shape behaves like (1,3), giving

$$C_{ij}=A_{ij}+B_j,\qquad i=0,1;\ j=0,1,2.$$

The right vector is reused across rows. In (2,3)+(2,), the final sizes are 3 and 2: neither is one, so no such output correspondence exists.

Reducing axis one of a 2×3 output yields

$$R_i=\sum_{j=0}^{2}C_{ij}.$$

The result has shape (2,), not (2,1); this chapter does not keep a removed dimension as an extra size-one axis.

## Worked examples: actual values and batched reuse

The canonical left matrix is [[1,2,3],[4,5,6]], while the right vector is [10,11,12]. Broadcasting produces [[11,13,15],[14,16,18]]. At output [1,1], left [1,1] contributes 5 and right [1] contributes 11, so the result is exactly 16.

Reducing axis one produces [39,48]. Reducing axis zero instead produces [25,29,33]. The shape identifies which positions are combined; summing all positions would instead produce the scalar 87.

In the batched preset, (2,1,3)+(1,4,1) produces (2,4,3). The left input is reused along the middle axis; the right is reused along batch and final axes. Reducing the final axis produces shape (2,4) and values [[36,39,42,45],[45,48,51,54]].

For (0,3)+(1,3), the output has shape (0,3) and contains no elements. Reducing axis zero yields three exact zeros, one empty sum per remaining column. Empty arrays are valid shapes under this bounded policy, not fabricated data.

## Common mistakes and counterexamples

Broadcasting aligns trailing dimensions, not the first dimension that happens to have an equal size. A shape-(2,) vector does not automatically mean “one value per row” of a 2×3 matrix; use a size-one trailing dimension when that is the intended operation.

Elementwise multiplication and matrix multiplication use different rules. A reduction removes the selected axis here, while broadcasting can introduce or reuse an axis. Do not call every array a geometric vector or assume vectorization changes the underlying mathematical operation into a dot product.

## Numerical considerations

The explorer uses small consecutive integers and exact rational operations, so its shape/value checks are exact. Real numerical libraries may use floating dtypes, different accumulation precisions and different reduction orders; valid shapes do not ensure numerical reliability.

The elementwise operation count equals the number of allocated output elements. Index mapping, memory access, temporary arrays and reduction work add costs. A vectorized expression can reduce interpreter overhead, but this lesson does not infer wall-clock speedups without a meaningful workload measurement.

## Engineering and ML connections

Tensor shapes appear in feature matrices, batches, channels, logits, targets and loss reductions. Explicit axes prevent an operation from accidentally combining samples when it should combine features or vocabulary positions. Inspect shapes and representative indices before optimizing a computation; a fast operation on the wrong correspondence is still wrong.
