## Conventions in force

These apply across the whole book (master plan §3) and are what the stage above follows.

- The plane has $+x$ to the right and $+y$ **up**. Screen coordinates, where $y$ points down, are converted in exactly one place.
- Vectors are columns, $\mathbf v=\begin{bmatrix}x\\y\end{bmatrix}$. Matrices act from the left, $\mathbf v'=A\mathbf v$, and if $A$ acts first then $B(A\mathbf v)=(BA)\mathbf v$.
- Angles are in radians; degrees appear only as a secondary display.
- $=$ means exactly equal and $\approx$ means a rounded approximation. A rounded number is never shown with an equals sign.

## Mathematical typography

Inline mathematics sits in the line: the vector $\mathbf v=(3,2)$ has components $x=3$ and $y=2$, and its length is $\lVert\mathbf v\rVert=\sqrt{x^2+y^2}$. Display mathematics gets its own line:

$$
\lVert\mathbf v\rVert=\sqrt{x^{2}+y^{2}},\qquad \theta=\operatorname{atan2}(y,x).
$$

A very long equation must never widen the page. This one is long on purpose, and on a phone it scrolls inside its own box, which becomes a keyboard-reachable region only when it actually overflows:

$$
\mathcal{L}(\theta)=-\frac{1}{N}\sum_{n=1}^{N}\sum_{i=1}^{V}y_{n,i}\,\log\frac{\exp\left(z_{n,i}\right)}{\sum_{j=1}^{V}\exp\left(z_{n,j}\right)},\qquad \mathbf{z}_n=W\mathbf{h}_n+\mathbf{b}
$$

## Exact and approximate

The inspector never lets a rounded value pose as an exact one.

| Quantity | Exact form | Approximation | Shown as |
| --- | --- | --- | --- |
| $\lVert(3,2)\rVert$ | $\sqrt{13}$ | 3.605551… | `= √13`, then `≈ 3.605551…` |
| $\lVert(3,4)\rVert$ | $5$ | none needed | `= 5` only |
| $\lVert(2.5,1.5)\rVert$ | not claimed | 2.915476 | `≈ 2.915476` only |
| direction of $(0,0)$ | undefined | none | `undefined`, with the reason |

The trailing "…" appears only when the exact value is known to be irrational. For $(2.5,1.5)$ the model makes no claim about an exact form, so it shows only what it computed.

<Callout kind="numerical">
`np.linalg.norm` squares before it adds, so for a tiny vector such as $(10^{-200},10^{-200})$ it returns `0.0`, although the vector is not zero. `np.hypot` and `math.hypot` rescale first and are correct. The independent Python oracle found this while checking the browser model, which uses `Math.hypot`.
