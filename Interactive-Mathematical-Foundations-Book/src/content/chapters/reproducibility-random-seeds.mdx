## Intuition: a reproducible computation has a specification

A seed names a starting point only after the pseudorandom generator and its state interpretation are specified. An operation sequence, input values and comparison policy are likewise part of a numerical experiment. Two runs can share a seed yet use different random algorithms or arithmetic orders.

The explorer uses one explicit uint32 generator, records every before/after state and exposes the actual uniform fractions. It independently replays the same specified stream and checks discrete states exactly. Rendering never draws from a global or unseeded random source.

The contrasting arithmetic experiment is also deterministic. It evaluates the same three represented operands with two association orders, producing a controlled numerical variation. This demonstrates a reason parallel or changed reductions can differ; it does not pretend that this sequential simulator is itself nondeterministic hardware.

## Definition: seed, state and numeric agreement

The fixed generator is a 32-bit linear congruential generator:

$$s_{k+1}=(1664525s_k+1013904223)\bmod2^{32},$$
$$u_k=s_{k+1}/2^{32}.$$

Seed and state lie in 0 through $2^{32}-1$. The uniform values are exact dyadic fractions in [0,1); this simple educational stream is not a cryptographic generator or a general randomness-quality recommendation.

For finite numerical results x,y, the chosen comparison accepts

$$|x-y|\le a_{\mathrm{tol}}+r_{\mathrm{tol}}\max(|x|,|y|).$$

Absolute tolerance carries the result's units; relative tolerance scales with magnitude. Exact discrete outcomes such as generator states, shape dimensions and sample counts are compared exactly. Non-finite arithmetic requires its own explicit policy and is not silently accepted by this finite-value comparator.

## Mechanics: record what actually happened

Each sample record contains index, prior uint32 state, next uint32 state, actual uniform value and its exact fraction. The replay column records the same algorithm run again from the recorded initial state. The semantic trace is immutable: stepping backward selects a recorded event rather than trying to reverse an RNG mutation.

The association experiment records stored a,b,c, the first sum a+b, the first sum b+c, both final answers, an exact intended-decimal reference and signed/absolute/relative errors. The tolerance comparison between the two computed answers is separate from either answer's error to the mathematical reference.

Changing the seed or a numeric operand changes canonical state and recomputes the experiment. A rejected seed, count, non-finite operand or invalid tolerance never becomes part of mathematical rendering.

## Derivation: state recurrence and nonassociativity

The recurrence advances exactly one specified uint32 state per sample. Since the modulus is a power of two, its recorded state identifies the next experiment step unambiguously for this algorithm. Resuming from a saved state reproduces a suffix of its stream when the same operations are used.

Real addition is associative, but a floating-point addition generally rounds after each operation. Thus

$$\operatorname{fl}(\operatorname{fl}(a+b)+c)$$

can differ from

$$\operatorname{fl}(a+\operatorname{fl}(b+c)).$$

Changing grouping changes which small terms may be lost before later cancellation. A compiler, library, vectorized reduction or parallel execution can choose a different sequence. Identical mathematical notation does not fully specify that numerical sequence.

A numerical budget should come from input uncertainty, algorithm error and required output accuracy. Making a budget large enough to hide a difference is a demonstration of acceptance under that budget, not a justification for choosing it.

## Worked examples: replay and a changed association

Starting from state 42, the first two next states are exactly 1083814273 and 378494188. Their uniforms are those integers divided by $2^{32}$. The next states are 2479403867, 955863294, 1613448261 and 110225632. These are the actual committed sample sequence, not decorative histogram bins.

The resume preset starts at recorded state 378494188 and requests four samples. It reproduces the final four states of the six-sample experiment. Record the algorithm and the state, not just a statement that “seed 42 was used.”

For represented a=1e16, b=−1e16 and c=1, the exact mathematical sum is one. Left association first forms a+b=0 and returns one. Right association forms b+c=−1e16 because the one is rounded away, then returns zero. The absolute answer errors are zero and one respectively.

With both default tolerances 1e-12, the measured difference one exceeds the comparison budget. The loose-budget preset instead uses absolute tolerance one and relative tolerance zero, so the comparison accepts. The right answer still has exact error one; the acceptance flag did not change the mathematical reference.

## Common mistakes and counterexamples

A seed alone does not identify arbitrary RNG implementations, initial state layouts or sample-consumption patterns. A fixed algorithm can also produce a different later draw if a previous code path consumed extra samples. Record version, algorithm, state and draw order when those matter.

Floating-point equality is suitable for exact discrete states and specified binary64 reference results. It is not a substitute for a budgeted approximation check on a computed transcendental answer. Conversely, a tolerance should never permit an incorrect index, sample count or RNG state to pass as “close enough.”

## Numerical considerations

The LCG recurrence uses the accepted explicit uint32 seeded utility; Python independently computes the same modular integers without copying its floating implementation. Its uniforms fit exactly in binary64 because their denominator is $2^{32}$. The actual stream is deterministic under that specified contract.

The arithmetic-order comparison uses actual JavaScript binary64 operations at fixed represented inputs. Its exact intended reference remains rational. Across environments, elementary functions, fused operations, accumulation precision, subnormal handling and reduction order can still differ. After a platform or library upgrade, record the code version, repeat the same inputs and sample sequence, and compare approximate results using justified tolerances; a seed alone does not settle every difference.

Routine mathematical rendering contains no unseeded randomness. User-started trace playback changes only which immutable frame is selected; elapsed time does not generate a new numerical sample.

## Engineering and ML connections

A useful experiment record includes code/source revision, inputs and their storage dtypes, random algorithm and seed/state, sample order, numerical algorithm, environment/library versions and comparison budgets. This supports reproducible diagnostics without pretending all hardware runs must be bit-identical.

In training, data order, stochastic sampling, parallel reductions and mixed precision can interact. Decide which outcomes must match exactly and which require a justified approximate allowance. Preserve evidence for both successful and failed checks so a corrected run remains independently reviewable.
