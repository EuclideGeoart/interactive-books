<Section id="intuition" number="02" title="Recursion and an explicit stack share a continuation." kicker="THE INTUITION">

A recursive DFS call implicitly remembers the current vertex and where its neighbor loop will continue. This implementation makes that information explicit. Pushing a frame models entry; popping a completed frame models return.

Chapter 2’s stack provides last-in, first-out discipline, and Chapter 12’s tree traversal introduced suspended callers. A graph needs a discovery guard as well: cycles and shared descendants mean a neighbor may have been seen already. A tree-only recursion pattern would revisit forever on a cycle.

</Section>

<Section id="memory" number="03" title="Avoid references across vector growth." kicker="STRUCTURE / MEMORY LAYOUT">

Each frame holds three integers. The native algorithm reads the top frame by index/access, copies the current neighbor, advances the cursor, and only then pushes a child. It does not retain a reference to a vector element across push_back, which could relocate frame storage.

Color and predecessor arrays are separate from the frame stack. WHITE is unseen, GRAY is discovered and unfinished, BLACK is complete. The output records discovery order, while BLACK marks completion. Discovery order and finishing order are different quantities.

</Section>

<Section id="operations" number="04" title="Single-source search or a full forest." kicker="INTERACTIVE OPERATIONS">

<Section id="implementation" number="05" title="The cursor prevents work from restarting." kicker="C++ IMPLEMENTATION">

The complete standalone header returns typed state containing actual frames, colors, predecessors, output, and counters. Before a descent, the caller’s next index increments. After return, the top frame resumes from that saved index. Frame depth cannot exceed V because only WHITE vertices receive child frames.

The same helper has a detection flag used by Chapter 32. Ordinary DFS does not report cycles just because it encounters seen vertices; it simply avoids revisiting them. There is no native recursion, so graph depth cannot exhaust the process call stack.

<Section id="pointer-trace" number="06" title="Finish before backtracking." kicker="CODE + VISUALIZATION TRACE">

When a frame cursor reaches the end of its adjacency row, the vertex becomes BLACK. The next statement pops the frame. Only a later resume statement activates the caller beneath it. The brief BLACK frame is therefore a real completed-statement snapshot.

Inspect advances the cursor before choosing whether to descend. The exact undirected parent edge is skipped, while other seen edges remain inspected. The predecessor assignment occurs before discovery, and the frame push follows discovery; each state is preserved independently.

</Section>

<Section id="invariants" number="07" title="A vertex receives at most one discovery frame." kicker="INVARIANTS">

Every predecessor edge exists in the correct direction. Colors never move backward from BLACK to GRAY or GRAY to WHITE during a run. Queue uniqueness is irrelevant to DFS scheduling, but output uniqueness still holds because discovery happens once.

Each frame cursor lies between zero and its adjacency row length. The frames form the active search path apart from brief statement boundaries during push/pop. Completion requires an empty frame stack. A forest additionally discovers every vertex.

</Section>

<Section id="complexity" number="08" title="Deep work changes space, not linear traversal time." kicker="COMPLEXITY EXPLORER">

<GraphComplexity kind="dfs" />

Compare Dense, Single vertex, and a custom chain. Adjacency / cell reads count each examined adjacency entry; output counts unique discoveries; Search launches counts forest roots. In a chain, the frame stack reaches V. A wide star has many neighbor reads but a shallow active stack.

For prepared adjacency lists the traversal costs O(V + E), with O(V) color/predecessor arrays and at most O(V) frames. Row construction is O(V + E); the bounded pairwise validator is separate O(V² + E²) setup. Snapshot retention is visualizer overhead rather than the canonical algorithm’s auxiliary bound.

</Section>

<Section id="analogy" number="10" title="Keep a finger on every unfinished page." kicker="REAL-WORLD ANALOGY">

Read a nested instruction, leave a marker at its next step, and follow the newly referenced instruction. On completion, return to the most recent marker. The markers are frames; their page positions are neighbor cursors. Finishing an instruction does not erase the underlying object.

</Section>

<Section id="engineering" number="11" title="Explicit frames make depth and pause/resume visible." kicker="ENGINEERING INSIGHT">

Compilers, graph analyzers, and dependency tools often need entry and exit semantics. An explicit frame stack can support finishing times or pause/resume without uncontrolled recursion depth. Such extra outputs would require their own fields and invariants; this chapter records discovery order and completion colors only.

</Section>

<Section id="exercises" number="12" title="Explain a return without moving a node." kicker="EXERCISES / CHALLENGES">

At the deepest default state A,B,D, what cursor must B retain? Its parent edge to A and discovery edge to D have been examined, so the next entry is E. After D’s pop, B resumes there.

Challenge: create two disconnected directed regions and compare single-source DFS with DFS forest. A forest covers all vertices but does not imply strong connectivity or one path visiting them all.

</Section>

<Section id="summary" number="13" title="Backtracking is restored continuation state." kicker="CHAPTER SUMMARY">

DFS marks vertices once, retains a cursor for each unfinished search, and backtracks only after a row is exhausted. Explicit frames match recursion’s mechanics while bounding storage in a vector. Chapter 28 adds direction as a reachability constraint.
