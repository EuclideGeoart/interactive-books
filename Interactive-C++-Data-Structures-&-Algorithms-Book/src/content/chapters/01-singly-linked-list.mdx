<Section id="mental-model" number="01" title="Start with the connections." kicker="VISUAL MENTAL MODEL">

A linked list is a chain, not a row of boxes in memory. Each node knows just one thing about the structure: **where the next node lives.**

<MentalModel />

<div className="three-observations"><div><span>01 / THE ENTRY POINT</span><h3>Start at head.</h3><p>The list owns a single pointer to its first node. An empty list has <code>head == nullptr</code>.</p></div><div><span>02 / THE RELATIONSHIP</span><h3>Follow next.</h3><p>Each <code>next</code> field stores an address, connecting one object to another.</p></div><div><span>03 / THE BOUNDARY</span><h3>Stop at nullptr.</h3><p>The last node points nowhere. Check for null before reading a node’s fields.</p></div></div>

</Section>

<Section id="intuition" number="02" title="Order is a relationship." kicker="THE INTUITION">

<div className="prose-columns"><div><p>In an array, the next element is found by arithmetic. In a linked list, the next element is found by reading a pointer. You can connect objects that live far apart in memory.</p><p>To insert a node, you change relationships. Existing values stay where they are. But to find the fifth node, you must follow four links from the first.</p></div><div className="comparison-note"><span className="eyebrow">THE TRADE-OFF</span><h3>Cheap rewiring.<br/>Sequential discovery.</h3><p>Insertion after a <em>known node</em> is O(1). Finding that node can still take O(n).</p></div></div>

</Section>

<Section id="memory" number="03" title="Two fields. Separate allocations." kicker="STRUCTURE & MEMORY">

<Section id="implementation" number="05" title="The whole implementation." kicker="CANONICAL C++20">

This class owns every allocated node and releases them in its destructor. Copying is disabled to prevent two lists from owning the same chain; moving transfers ownership and empties the source. `find()` returns a borrowed, read-only node pointer that becomes invalid when its node is erased or the list is destroyed.

<FullSource />

<Callout title="Allocation failure leaves the list unchanged." tone="green">If <code>new</code> throws <code>std::bad_alloc</code>, no existing link has been modified. The operations that only traverse or release nodes do not allocate. Cleanup is iterative, so destroying a long list does not grow the call stack.</Callout>

</Section>

<Section id="pointer-trace" number="06" title="A link changes before head does." kicker="CODE ↔ POINTER TRACE">

For insertion at the head, the order of these two assignments is the entire algorithm. The new node must keep the old chain reachable before it becomes the entry point.

<div className="trace-walkthrough"><div><span className="trace-index">1</span><div><code>newNode-&gt;next = head;</code><h3>Keep the old entry point.</h3><p>The new node now points to the old first node. <code>head</code> still points to <code>10</code>.</p></div></div><div><span className="trace-index">2</span><div><code>head = newNode;</code><h3>Publish the new first node.</h3><p>Only now does <code>head</code> move to <code>5</code>. The path from <code>5</code> to the original chain already exists.</p></div></div></div>

<p><a className="text-link" href="#operations">Trace these assignments in the lab →</a> Choose Insert head, then click the line numbers to move between the two assignments.</p>

<Callout title="delete is not an unlink operation." tone="amber">Deletion first saves a pointer, then bypasses the node while it is alive, then destroys the object and releases its storage. The lab separates destruction and freeing on the same C++ line. A saved local pointer still holds the old address afterward; it is dangling until it leaves scope.</Callout>

</Section>

<Section id="invariants" number="07" title="Make correctness visible." kicker="INVARIANTS">

The live panel checks the list after every semantic event. It distinguishes a broken structure from a temporary condition inside a correct operation.

<div className="table-scroll"><table><thead><tr><th>Property</th><th>What it protects</th></tr></thead><tbody><tr><td>No live nodes ⇒ <code>head == nullptr</code></td><td>The empty state has no stale entry point.</td></tr><tr><td>Traversal eventually reaches <code>nullptr</code></td><td>No cycles, and no walk into an ended object lifetime.</td></tr><tr><td>All live nodes are reachable after the operation</td><td>The owning list has not lost an allocation.</td></tr><tr><td>Every structural link targets a live object or null</td><td>Freed storage is never treated as a valid node.</td></tr><tr><td>Dangling local pointers are never dereferenced</td><td>A saved address does not extend an object’s lifetime.</td></tr></tbody></table></div>

<p className="margin-note">△ <strong>Temporary is meaningful.</strong> A newly allocated node is detached before it is linked. A removed node is detached before it is deleted. The panel marks these transitions in amber; at the function boundary, reachability must be restored.</p>

<div className="mistake-list"><div><span>01</span><div><h3>Overwriting the only pointer.</h3><p>Setting <code>head</code> to null does not free the chain. <Section id="engineering" number="11" title="Where this becomes systems work." kicker="ENGINEERING INSIGHT">

<div className="engineering-grid"><div><span className="eyebrow">MEMORY ALLOCATORS</span><h3>A free list is a chain.</h3><p>A pool can link unused blocks through a next pointer. Taking the first free block resembles removing the head; returning a block resembles inserting at the head.</p></div><div><span className="eyebrow">EVENT & WORK CHAINS</span><h3>Stable objects, changing order.</h3><p>Links can organize objects without moving their storage. This matters when other parts of a system hold references to those objects.</p></div></div>

<Callout title="O(1) does not mean “fastest in practice.”">Pointer chasing adds dependent loads; separate allocations can scatter nodes and reduce cache locality. A <code>std::vector</code> often wins for scanning despite different insertion costs. Choose a linked structure for a measured ownership or rewiring need. <code>std::forward_list</code> is the standard singly linked container; this implementation exists to expose its mechanics.</Callout>
