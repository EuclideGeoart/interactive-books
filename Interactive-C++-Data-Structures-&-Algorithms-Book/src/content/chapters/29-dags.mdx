A and B define Line AB. Line AB and Circle C define Intersection P. Neither endpoint depends on the line that it defines. This graph is **directed** and has **no directed cycle**. Both properties are necessary: drawing arrowheads alone does not make a DAG.
</Section>

<Section id="intuition" number="02" title="A partial order leaves some choices open." kicker="THE INTUITION">
A **source** has indegree zero; a **sink** has outdegree zero. A is an immediate predecessor of Line AB; Line AB is a successor of A. Reachability extends this relationship transitively: A is an ancestor prerequisite of Intersection P even without a direct edge to P.

A and B may be created in either order. Neither must precede the other, but both must precede Line AB. This is a **partial order**. A topological order chooses one linear sequence consistent with it. Disconnected vertices are allowed, and an empty directed graph is a DAG. A self-loop is already a directed cycle.

Review <a href={`${import.meta.env.BASE_URL}chapters/28-directed-graphs/`}>directed reachability in Chapter 28</a>. Unlike a tree, a DAG may give one dependent several incoming prerequisites. A graph vertex has no implicit hierarchical parent.
</Section>

<Section id="memory" number="03" title="IDs connect records; they do not own objects." kicker="STRUCTURE / MEMORY LAYOUT">
The canonical graph owns an edge vector and an adjacency vector of **edge indices**. An edge stores `from` and `to` vertex IDs. An ID names a slot, not a memory address. The logical graph and storage rows derive from that same data.

A dependency edge carries ordering meaning; it does not imply C++ object ownership. Deleting a task record, freeing a geometry object, and removing its dependency edges are separate engineering decisions. This example borrows a const graph throughout the check; mutation during a trace is unsupported. The UI admits eight vertices, self-loops, and no parallel pairs. The native graph accepts parallel edge records and counts every record consistently.
</Section>

<Section id="operations" number="04" title="Prove that every dependency can be retired." kicker="INTERACTIVE OPERATIONS">

Count incoming dependencies, queue the sources, then retire outgoing edges after emitting ready work. If the queue empties before every vertex is emitted, a directed cycle exists.

<Section id="pointer-trace" number="06" title="Read the arrows as satisfied obligations." kicker="CODE + VISUALIZATION TRACE">
Step to the first emission of A. Line AB still has both incoming edges until A → Line AB is retired. After that decrement it has one remaining prerequisite, B. Emitting B and retiring B → Line AB makes the line ready. Circle C can be processed independently, but P must wait for both the line and circle.

Selection inspects arrays and adjacency without changing the algorithm. Previous restores the exact earlier snapshot, including counts and retired edges. Storage view does not invent pointer fields for an ID-based representation.
</Section>

<Section id="invariants" number="07" title="Acyclicity belongs to the entire directed graph." kicker="LIVE INVARIANTS">
A residual indegree equals the number of counted incoming edges that have not yet been retired. Every ready-queue entry has zero residual indegree. Every emitted vertex had all its prerequisites satisfied. Acyclicity remains pending until the check completes; it passes only if the output contains all V vertices.

A completed prefix is still useful evidence when a cycle blocks the rest, but it is not a complete topological order. Some residual vertices may merely depend on the cycle. Use <a href={`${import.meta.env.BASE_URL}chapters/32-cycle-detection/`}>Chapter 32's active-stack method</a> to recognize a back edge directly.
</Section>

<Section id="complexity" number="08" title="Visit vertices and dependency edges." kicker="COMPLEXITY EXPLORER">
<GraphComplexity kind="kahn" />
The checker counts E edges, removes each once, and queues/emits each of V vertices once: **O(V + E)** time and **O(V + E)** auxiliary state in this instrumented teaching implementation. A minimal checker can omit counted/removed diagnostic arrays and use O(V) algorithm space beyond adjacency. A matrix-based scan instead pays O(V²).
</Section>

<Section id="break-it" number="09" title="Make a dependency depend on its own result." kicker="COMMON MISTAKES / BREAK-IT MODE">
In the lab choose **Cycle with downstream blocked work**, then After. B depends on C and C depends on B. D depends on that cycle and is blocked too, while independent A and E can still be emitted. The final acyclicity invariant fails deliberately. Try the self-loop and compare it with the valid disconnected DAG.

Do not confuse a diamond with a cycle: A → B → D and A → C → D give two forward paths with no return path. Do not mistake a graph's geometric crossing for a vertex or dependency.
</Section>

<Section id="analogy" number="10" title="A recipe with independent preparations." kicker="REAL-WORLD ANALOGY">
You can prepare a sauce and boil pasta in either order or concurrently, but both must finish before plating. Requiring the plated dish before preparing its sauce creates a circular prerequisite. The graph captures what must happen before what; it does not by itself specify duration, resource capacity, or failure handling.
</Section>

<Section id="engineering" number="11" title="Dependencies support incremental recomputation." kicker="ENGINEERING INSIGHT">
When endpoint A changes, Line AB and then Intersection P may need recomputation; Circle C need not change. A system can first mark the affected successor closure dirty, then evaluate those dirty nodes when their prerequisites are available. The whole graph's topological order can be cached while topology stays unchanged.

Build systems combine dependency ordering with content hashes, cached artifacts and worker limits. Spreadsheets track formula dependencies; package managers add version constraints; geometry engines must also represent failed or undefined constructions. A DAG alone solves none of those extra policies. Production engines need not perform a complete topological sort on every value update.

Changing topology is a different operation from changing a value. Adding an edge can introduce a cycle and invalidate a cached order. A system must reject, diagnose or explicitly support that situation before treating the new graph as a DAG.
</Section>
