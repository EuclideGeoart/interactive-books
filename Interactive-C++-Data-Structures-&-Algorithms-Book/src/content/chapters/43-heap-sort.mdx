<Section id="mental-model" number="01" title="One array has an active heap and a finished suffix." kicker="VISUAL MENTAL MODEL">

A max heap puts its largest active key at index 0. Swap that root with the final active slot, reduce heapSize by one, and repair the new root with sift-down. The removed maximum remains in its final array position. Repeating this process grows an ascending suffix from right to left.

This is the same complete-tree index geometry as <a href="../09-binary-heap/">Chapter 9 Binary Heap</a>. The shape remains complete even while parent ordering is temporarily broken during a sift.

</Section>

<Section id="intuition" number="02" title="Extract the maximum without throwing its slot away." kicker="THE INTUITION">

First build a max heap bottom-up, beginning at the last internal node. Each node's child subtrees are already heaps when that node is processed. Next exchange the root with the last active record. The suffix no longer participates in comparisons or swaps.

Chapter 9 extraction removes the last vector element after saving the result. Sorting must retain that storage, so this chapter adapts the same sift-down rules to an explicit active-prefix bound. It does not construct another owning heap and does not shrink the vector.

</Section>

<Section id="memory" number="03" title="The heap boundary is a number, not a second allocation." kicker="STRUCTURE / STORAGE LAYOUT">

The canonical function owns one vector of records. Tree and array views project the same indexed storage; there are no allocated tree nodes or parent pointers. Left child is `2i+1`, right child is `2i+2`, and parent is `(i−1)/2` for a nonroot index.

Algorithmic extra space is O(1): heapSize, a few indices and temporary swap storage. Sift-down is iterative and no recursive sorting calls are made. Input ownership, observer metadata and browser trace snapshots are excluded from that claim. Identity letters remain attached to records throughout swaps; a fixed index is a storage location, not a permanent record identity.

</Section>

<Section id="pointer-trace" number="06" title="Every comparison belongs to the current active prefix." kicker="CODE + VISUALIZATION TRACE">

Root identifies the next internal node during bottom-up construction. Has child tests the arithmetic guard. Left and Right compute candidate indices. Choose records the bounds check and the optional child-key comparison; Ordered compares the chosen child with the parent. Swap mutates two slots, and Advance moves the sift cursor down one level.

During extraction, Extract executes the root/end swap. Shrink finalizes that end slot and reduces heapSize. The next child tests use the new boundary, so no finalized slot can reenter the heap. Facts report the active count and the exact finalized count independently of color.

</Section>

<Section id="invariants" number="07" title="Complete shape, heap order and suffix order are separate." kicker="INVARIANTS">

Active indices are exactly `[0, heapSize)`, preserving complete-tree shape. At Built and Restored boundaries, each parent is at least as large as every active child. During building or repair, this ordering can be pending while the shape remains valid.

The suffix is always ascending and every active key is no larger than its first key. Each swap preserves the full input permutation. The live invariant panel distinguishes temporary heap-order repair from a finalized-suffix error. Sibling order is unconstrained; a heap is not a fully sorted array.

</Section>

<Section id="complexity" number="08" title="Building is linear; repeated repairs are logarithmic." kicker="COMPLEXITY EXPLORER">

<SortingComplexity chapter="43" />

Most nodes sit near the leaves and require little sift work. Summing the heights of all internal nodes gives O(n) bottom-up construction, rather than n independent root-to-leaf insertions. Each of the n−1 extraction repairs follows at most O(log n) levels, so the whole sort is O(n log n).

Key comparisons count right-versus-left only when the right child exists, plus chosen-child-versus-parent. Bounds tests are not key comparisons. Each executed swap counts two array writes. Passes count extraction swaps; recursion and temporary-buffer writes stay zero. This operation model excludes observer and rendering overhead.

</Section>

<Section id="break-it" number="09" title="The finalized suffix must never be sifted again." kicker="COMMON MISTAKES / BREAK-IT EXPERIMENTS">

Load `2,1,3` and pause at Built. The root must be 3, and both child edges must satisfy heap order. After Extract and Shrink, the 3 is outside the active tree. Predict what would happen if down still used the full vector size: it could pull that finalized maximum back into the heap.

Use `3,1,4,0,2,5` to find a Choose step where the right child outranks the left. Always choosing left can stop under a too-large right child. The canonical code checks the right bound before reading, so a lone left child does not cause an out-of-range access.

</Section>

<Section id="analogy" number="10" title="A tournament retires its winner into a ranked display." kicker="REAL-WORLD ANALOGY">

The tournament tree exposes the strongest remaining contestant at its root. Move that contestant into the last available display slot, close that slot to the tournament, then repair the path affected by the replacement contestant. The display fills from greatest at the far right toward smallest at the left.

</Section>

<Section id="engineering" number="11" title="Worst-case bounds come with different access patterns." kicker="ENGINEERING INSIGHT">

Heap sort gives O(n log n) worst-case work and constant algorithmic auxiliary storage, but parent/child accesses jump through the array. That locality differs from <a href="../41-merge-sort/">merge sort's</a> sequential buffering and <a href="../42-quick-sort/">quicksort's</a> partition scans. Equal records can cross during long swaps, so ordinary heap sort is unstable.

A max heap used as a priority queue and a max heap used for sorting share ordering mechanics but have different ownership goals. The former removes returned values; the latter preserves every record in the same array. Keeping that distinction explicit avoids unnecessary copies and a second heap owner.

</Section>

<Section id="summary" number="13" title="Keep the maximum, shrink the heap, repair the root." kicker="CHAPTER SUMMARY">

Bottom-up construction creates a max heap in O(n). Each extraction swaps a maximum into its final suffix slot, shrinks the active bound and applies the established sift-down mechanics. The complete sort uses O(n log n) time and O(1) algorithmic extra storage, with no stability guarantee.
