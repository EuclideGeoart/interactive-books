<Section id="intuition" number="02" title="Capacity triggers subdivision; depth guarantees termination." kicker="THE INTUITION">

With capacity 2, a leaf may hold two points without splitting. Inserting a third point first makes it overfull. If its depth is below the configured maximum, split both coordinate intervals at their midpoints, create four children, and redistribute all three points. If a child is still too full, apply the same rule there.

Number child slots by xHigh + 2 × yHigh: 0 is low x/low y, 1 high x/low y, 2 low x/high y, and 3 high x/high y. Equality with either midpoint selects the high side. Drawn child closures share an edge, but ownership follows this unique routing rule.

Duplicate coordinates always choose the same child. Repeated subdivision cannot separate them. At maximum depth, keep an overflow leaf instead of recursing forever. The root has depth zero, so maximum depth zero disables subdivision entirely.

</Section>

<Section id="memory" number="03" title="Leaves own point IDs; internal nodes own four links." kicker="STRUCTURE / MEMORY LAYOUT">

Each node stores its bounds, depth, parent ID, child slots, and leaf member IDs. Internal nodes have four child links and no stored points. Leaves have no child links. The root exists even when the input is empty, so an empty quadtree differs from a null KD-tree root.

During splitting, the old leaf members move into an explicit pending list before child placement begins. Each live point is owned by exactly one leaf or one pending slot. This is algorithmic state rather than a rendering trick: playback can stop after the split without losing or duplicating points.

The C++ vector owns nodes by value and uses integer node indices. Inserting a child may reallocate the vector, so mutation code retains an index and reacquires the parent rather than keeping a reference across allocation. Parent IDs and diagram positions are not native addresses. Copying or moving the returned value follows normal vector ownership.

</Section>

This canonical implementation is point-only. It accepts at most 12 unique A–Z identities, finite coordinates in [−8,8], integer capacity 1 through 8, and maximum depth 0 through 6. Closed queries accept boundary points and zero extent. Invalid/reversed bounds and out-of-root insertions are rejected. The complete header needs only the C++20 standard library.

A future AABB version should retain a spanning object at its current parent and descend only when exactly one child fully contains it. Query traversal must test parent-held objects before children. That is a different storage contract from this point-only lab; the code does not silently duplicate boxes into every intersected child or pretend that a box's center represents its full extent.

<Section id="pointer-trace" number="06" title="An overfull leaf is a real intermediate state." kicker="CODE + VISUALIZATION TRACE">

Route chooses the current node. Store appends the point and removes its pending slot. Only after that statement does the capacity condition trigger Split. Split clears the parent membership, creates its children, and records the detached batch. Redistribute identifies the next pending point; subsequent Route and Store steps restore its leaf ownership.

The query starts after construction. Visit counts a node and checks its bounds. Prune rejects a disjoint region before testing its members or descendants. An overlapping leaf supplies candidates; Test applies exact closed point containment, and Accept records a result. A point on a drawn split edge may require conservative visits to both touching region closures, but it still has one stored owner.

At maximum depth, Limit explains why excess occupancy is valid. At Done, all placement is complete. Source highlighting names the corresponding canonical statement rather than a drawing update.

</Section>

<Section id="invariants" number="07" title="Subdivision changes ownership without changing coordinates." kicker="INVARIANTS">

All live points occur once across leaf storage and pending slots. Internal nodes own no points. Every child has one parent, depth parent + 1, and precisely the quadrant bounds selected by its slot. Child bounds remain inside the parent.

Every stored descendant follows the high-side rule at every ancestor. Merely testing inclusive child containment would be insufficient: a point on a shared boundary geometrically lies in both drawn closures. The routing invariant checks the selected slot, so duplicate ownership cannot hide behind touching boxes.

Completed leaves satisfy capacity unless their depth equals maximum depth. Before construction, placement is pending. Immediately after an overfull Store and before Split, the capacity condition is pending rather than a settled failure. No completed state may leave redistribution unfinished.

</Section>

<Section id="complexity" number="08" title="Refinement costs depend on depth and local crowding." kicker="COMPLEXITY EXPLORER">

<SpatialExplorer kind="quadtree" />

Compare uniform and clustered scenes with the same capacity. Read Visited nodes, Point tests, Pruned branches, and Tree depth. Increase maximum depth for duplicates: deeper refinement creates more nodes without separating coincident points. These counters expose mechanics; they are not timing benchmarks.

With direct record access, routing to a leaf costs O(D), and a split additionally redistributes its members. Building n points is bounded by O(nD) routing work for fixed four-way branching, plus allocation, with n points and maximum depth D; node storage is O(1 + nD) in the bounded adaptive tree. A full depth-D quadtree can contain (4^(D+1) − 1) / 3 nodes. Sparse point occupancy rarely justifies that uniform expansion.

For a particular range, geometric traversal costs O(V + T), where V is visited nodes and T is tested points; reporting K answers costs at least Ω(K). Worst-case traversal scans all allocated nodes and all points. A balanced-looking picture does not give a universal logarithmic range bound, and a boundary-aligned point lookup can visit multiple region closures.

The teaching C++ resolves point IDs with linear scans, so its query costs O(V + Tn + K log K), including sorted output. Its repeated pending-ID erasures and point lookups make a conservative build bound O(n²(D + 1)). The TypeScript projection also resolves node IDs linearly. Every lab run rebuilds the input and copies playback snapshots; these costs are separate from displayed traversal counts.

</Section>

<Section id="break-it" number="09" title="Boundary and duplicate scenes challenge the split rule." kicker="COMMON MISTAKES / BREAK-IT EXPERIMENTS">

Set capacity 1 and use several copies of 0,0. Predict the path at the root and every later split. If routing uses inclusive containment in a loop over children, a boundary point can be inserted multiple times. If equality always goes low during insertion but high during lookup, a result can disappear.

Set maximum depth zero and build duplicates. Rejecting the legal overflow would confuse a stopping policy with corruption. Removing the depth guard in a local copy demonstrates why capacity alone does not terminate coincident-point subdivision.

Pause at Split and predict what happens if the parent keeps its old members while children receive copies. The unique-ownership check would fail. Try an insertion outside [−8,8] or a reversed query in the safe lab to exercise input validation.

</Section>

<Section id="analogy" number="10" title="Split a crowded map tile into four smaller maps." kicker="REAL-WORLD ANALOGY">

A surveyor begins with one map covering a district. When too many survey markers occupy it, the map gains four child tiles and delegates each marker to exactly one tile. Quiet areas retain coarse tiles. At the permitted resolution limit, several markers may share a tile; the surveyor must inspect them individually.

<Section id="engineering" number="11" title="Adaptive space helps local density but needs object policy." kicker="ENGINEERING INSIGHT">

Point clouds, 2D scene culling, terrain subdivisions, and spatial picking benefit when dense regions need more detail than empty ones. Midpoint splitting gives predictable regions, but strongly clustered or coincident data can create long narrow paths. A moving point may need removal and reinsertion; that lifecycle is not supplied by this chapter's point insertion API.

For CAD rectangles or large game objects, retaining spanning AABBs at parents avoids ambiguous duplication, but can leave large candidate sets near the root. <a href="../64-r-trees/">R-trees</a> and <a href="../65-bounding-volume-hierarchies/">BVHs</a> organize object bounds differently. <a href="../62-octrees/">Octrees</a> add genuine depth to spatial subdivision, with a steeper memory-growth risk.

</Section>

<Section id="summary" number="13" title="Adaptive regions require a precise stopping and ownership rule." kicker="CHAPTER SUMMARY">

A point quadtree splits crowded leaves into four midpoint regions and redistributes members through unique high-side routing. Maximum depth makes coincident points safe. Closed queries prune disjoint regions and test remaining points exactly. The hierarchy adapts to density, while explicit storage policy and metadata costs determine its real engineering behavior.
