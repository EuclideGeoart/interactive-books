<Section id="intuition" number="02" title="Zero means no remaining prerequisite." kicker="THE INTUITION">
Kahn repeatedly chooses a vertex with no unsatisfied incoming edge, emits it, and satisfies each outgoing dependency. If any vertices remain in a finite directed graph but none is ready, following remaining incoming edges must eventually revisit a vertex: a directed cycle prevents completion.

FIFO is a tie policy, reused from <a href={`${import.meta.env.BASE_URL}chapters/06-queue-deque/`}>Chapter 6</a>. A min-priority queue can choose the smallest currently ready ID but adds queue cost. This implementation seeds sources in ascending vertex ID, then enqueues successors in edge input order. It promises determinism for the same input, not a unique mathematical answer or globally lexicographically smallest order.
</Section>

<Section id="memory" number="03" title="Keep indegrees separate from graph structure." kicker="STRUCTURE / MEMORY LAYOUT">
The const graph stores edges plus outgoing lists of edge indices. A state object owns indegree, counted/removed flags, a `std::deque` ready queue, an output vector, and the current vertex/edge. Graph edges remain intact; **removed** means logically retired by the algorithm, not erased from their vector.

An indegree index names a vertex. Edge flags index edges. Those arrays have different domains. All IDs are checked during graph construction. The observer uses signed −1 for “no current vertex/edge”; stored graph indices remain `std::size_t`. The native teaching implementation bounds vertices and edges to one million before running, keeping its observer casts representable.
</Section>

<Section id="pointer-trace" number="06" title="Emission and edge retirement are distinct events." kicker="CODE + VISUALIZATION TRACE">
In the diamond, stop just after emitting A. Output is [A], queue is empty, B and C still have indegree 1, and no edge has retired yet. Inspect A → B, then retire it: B becomes zero. **Only the next enqueue statement** places B into the queue. A → C is still pending at this point.

After both decrements and enqueues the queue is [B,C]. Popping B removes it before it is emitted. Retiring B → D changes D from 2 to 1. Only C's later decrement can make D ready. The counts show why D cannot jump ahead merely because one prerequisite finished.
</Section>

<Section id="invariants" number="07" title="Count exactly the edges that still matter." kicker="LIVE INVARIANTS">
<ul><li>Residual indegree equals counted incoming edges minus retired incoming edges.</li><li>Every queued vertex is distinct, not yet emitted, and has zero residual indegree.</li><li>Every output vertex is distinct and had zero residual indegree when emitted.</li><li>At completion, exactly V emitted vertices proves the graph acyclic.</li></ul>
The first rule holds during setup and halfway through processing outgoing edges. Emitting a vertex does not instantly erase its entire adjacency list. No invariant requires a newly-zero target to already be queued before the enqueue statement executes.
</Section>

<Section id="complexity" number="08" title="Every edge contributes two visits." kicker="COMPLEXITY EXPLORER">
<GraphComplexity kind="kahn" />
There are E initial counts and E outgoing inspections on an acyclic graph; each vertex is seeded or enqueued once and popped once. Total time is **O(V + E)**. The counters show actual edge visits, queue pops and indegree writes for the selected graph. Cyclic runs can stop before all outgoing edges are visited.

The diagnostic counted/removed arrays cost O(E); indegrees, queue and output cost O(V). A production implementation that needs only the order and cycle flag can omit per-edge diagnostics. Matrix traversal pays O(V²) instead of adjacency-list O(V + E).
</Section>

<Section id="analogy" number="10" title="Release work when its last prerequisite finishes." kicker="REAL-WORLD ANALOGY">
An assembly station waits for several parts. Each delivered part removes one outstanding requirement. The last delivery moves the station into the ready queue; the queue still determines when a worker takes it. Being ready and already executing are different states, just as enqueue and pop are different statements.
</Section>

<Section id="engineering" number="11" title="Topological readiness is one layer of a scheduler." kicker="ENGINEERING INSIGHT">
Build engines, dependency evaluators and task schedulers often propagate readiness in this style. Real scheduling also tracks worker capacity, durations, cancellation and failure. Here **emit** means “place into an order,” not “a concurrent task has finished.” A concurrent executor should satisfy outgoing dependencies after successful completion, using an appropriate synchronization policy.

Incremental recomputation may reuse a cached order, process only dirty descendants or maintain order dynamically. It need not run a complete topological sort after every value update. The DAG example in <a href={`${import.meta.env.BASE_URL}chapters/29-dags/`}>Chapter 29</a> separates topology changes from changed inputs. Always define whether arrows mean prerequisite → dependent before computing the counts.
</Section>
