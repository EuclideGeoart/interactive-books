<Section id="intuition" number="02" title="The operation contract survives a representation change." kicker="THE INTUITION">

Insert a new key increases size. Assigning an existing key changes its mapped value and keeps size unchanged. Find returns an optional integer; a missing key is different from a key mapped to zero. Contains returns whether a key exists. Erase reports whether it removed an entry. Capacity counts buckets, and α = size / capacity measures average bucket occupancy.

Update here means `insert_or_assign`: an absent key is inserted. It does not provide an update-only operation that fails on absence. The two lab buttons share this documented contract. Choosing a collision policy changes the mechanics, not these meanings.

</Section>
<Section id="memory" number="03" title="The bucket array is not the entry array." kicker="STRUCTURE / MEMORY LAYOUT">

Each bucket stores an owning pointer to its first node. Each node stores a key, mapped integer, cached full hash and owning next link. Empty buckets contain nullptr. Size counts nodes, not nonempty buckets: three entries in bucket 1 still contribute three to size. Separate chaining can hold more entries than buckets.

The initial six distinct keys occupy an 8-bucket map. Load is 6 / 8 = 0.75. Before adding a seventh distinct key, this example doubles capacity. Duplicate assignment checks equality first and does not trigger unnecessary growth. The policy is a teaching choice, not a universal requirement of hash tables or `std::unordered_map`.

</Section>

<Section id="pointer-trace" number="06" title="A resize is a sequence of transfers." kicker="CODE + VISUALIZATION POINTER TRACE">

Rehash first creates empty replacement heads. It detaches one old head into a local owner, reconnects the old bucket to its remaining chain, recomputes the detached node's bucket using the new capacity, attaches that new bucket's existing chain to the node, and publishes the node. Only after all entries move does it swap bucket arrays.

Two arrays coexist during this trace. Their capacities differ, so their mapping invariants use their own capacities. A temporary detached node is still live and owned locally. Node positions and illustrative addresses stay fixed; arrows describe the transfer. The final array swap changes the published capacity. Rehash may change traversal order and does not promise a sorted iteration order.

</Section>

<Section id="complexity" number="08" title="Expected constant time needs a distribution assumption." kicker="COMPLEXITY EXPLORER">

<HashDistribution id="hash-table-distribution" />

For bounded-size keys, useful distribution and bounded load factor, chained lookup has expected O(1 + α) work and therefore expected O(1) at a bounded α. The worst case remains O(n): all entries can share one bucket. The explorer measures real equality comparisons for every successful lookup. In a chain of n entries that total is n(n + 1) / 2, so the mean is (n + 1) / 2 and the longest lookup is n comparisons.

For arbitrary string length L, computing the hash and comparing keys also cost time; a blanket O(1) string lookup hides that dependence. Our teaching keys are bounded to twelve bytes. Rehashing costs O(n + m_new) here because it initializes the new array and relinks all nodes. Geometric growth spreads that cost over later insertions for expected amortized constant insertion under the stated assumptions. One insertion that grows the array is still expensive.

</Section>
<Section id="break-it" number="09" title="More buckets alone do not repair the mapping." kicker="COMMON MISTAKES / BREAK-IT MODE">

<HashBreakIt id="hash-table-break" />

Grow without remapping and i remains in old bucket 1 instead of new bucket 9. Insert a duplicate and the map no longer has one value per key. Forget a chain link and size can still report three although lookup can reach only one. The broken states are isolated browser models; Restore rebuilds a valid map.

</Section>
<Section id="analogy" number="10" title="Reorganize a warehouse without changing its inventory." kicker="REAL-WORLD ANALOGY">

A product key identifies a bin's contents. Adding aisles changes the routing directory, so every product must be assigned under the new rule. The inventory count does not increase because there are more aisles. Updating the quantity for an existing product does not create a second product identity.

</Section>
<Section id="engineering" number="11" title="The ADT does not choose locality or ordering for you." kicker="ENGINEERING INSIGHT">

Chaining buys simple collision handling and stable node addresses during rehash at the cost of pointer storage and separate allocations. Open addressing will place entries in one array and replace pointer traversal with a probe policy. An ordered map offers sorted traversal but different search mechanics. A small contiguous collection may beat hashing when allocation and indirection dominate. Choose using workload and contract requirements, not an unqualified complexity slogan.

This example exposes no iterators. A const bucket accessor exists for demonstrations and tests; its node pointers are observers and must never be deleted or rewired by callers. Public operations maintain exclusive ownership. Native pointer stability is meaningful only until that node is erased or the map is destroyed.

</Section>
