## The neuron contains the old predictor

In <a href={href('/chapters/linear-regression/')}>III-07 Linear Regression</a>, the frozen scalar predictor is ŷ=wx+b. Here the dot product generalizes that same affine mechanism to d features:

$$
z=w^Tx+b=\sum_{j=1}^d w_jx_j+b,\qquad a=\phi(z).
$$

For d=1 and identity activation, a=wx+b is exactly that scalar affine prediction in real arithmetic. The earlier chapter's predictor remains unchanged; this Part implements the vector extension with its own validated kernel. In III-07 a fitted weight could result from minimizing MSE. Here the parameters are supplied by us and the explorer never updates them from data.

An artificial neuron is a numerical function, not a biological cell simulation. Each weight scales one coordinate; the sum combines contributions; the bias shifts the preactivation; the activation transforms that scalar. A zero weight removes that feature's direct contribution. A zero input removes its contribution for that sample, even when the weight is nonzero. Neither fact means a parameter was learned to be irrelevant.

## Define values and shapes separately

The mathematical vectors x and w are d×1 columns. Their transpose product wᵀx is 1×1. The bias b, preactivation z and activation a are scalar values, represented as 1×1 in the shape inspector. The JSON interface stores columns as flat arrays; the canonical Python creates a NumPy column explicitly. It accepts one sample only, without implicit broadcasting or a batch convention.

The input x is an observation; w and b are parameters; φ is an explicitly selected function. These roles do not swap when we edit them. There is no target, loss, decision threshold, optimizer or evaluation metric in a bare forward pass. A sigmoid value in [0,1] could be used as a probability in an appropriately fitted and evaluated binary model, as in <a href={href('/chapters/logistic-regression/')}>III-13</a>; merely putting sigmoid here does not establish calibration or define a class decision.

## Derive the three output functions

Identity, ReLU and sigmoid are

$$
\phi_{\rm id}(z)=z,\qquad
\phi_{\rm ReLU}(z)=\max(0,z),\qquad
\sigma(z)=\frac{1}{1+e^{-z}}.
$$

Identity leaves the affine function unchanged. ReLU is piecewise linear: negative z gives 0, positive z gives z, and z=0 gives 0. It is continuous, but its derivative is not uniquely defined at zero. Forward evaluation at that point is perfectly defined. A later optimizer must state a derivative convention; this chapter implements none.

For very negative z, directly evaluating e⁻ᶻ can overflow. Multiply the numerator and denominator by eᶻ to obtain eᶻ/(1+eᶻ). The stable implementation therefore uses

$$
\sigma(z)=\begin{cases}
1/(1+e^{-z})&z\ge0,\\
e^z/(1+e^z)&z<0.
\end{cases}
$$

Every exponential argument is nonpositive. Real sigmoid is strictly between 0 and 1 for finite z; binary64 can round its positive tail to 1 and underflow its negative tail to 0. Those rounded endpoint outputs are disclosed, not treated as exact probabilities of certainty.

## Work the products by hand

For the opening x, w and b,

$$
w_1x_1=0.5(2)=1,\quad w_2x_2=2(-1)=-2,\quad
w^Tx=1-2=-1,\quad z=-1+0.25=-0.75.
$$

The outputs are identity −0.75, ReLU 0, and sigmoid approximately 0.3208213008. With x=(0,0) and b=2, both products and the dot vanish; identity and ReLU output 2 while sigmoid outputs approximately 0.880797078. The bias survives zero input. **Zero neuron** instead sets both inputs and bias to zero, retains the weights, and selects ReLU.

## Mistakes and numerical limits

Do not activate each contribution separately and then sum it: φ(Σwⱼxⱼ+b) is generally different from Σφ(wⱼxⱼ)+b. Do not discard a negative weight: its sign is part of the dot product. Do not omit the bias or silently change units. Do not report a ReLU zero as a class label, nor claim that a nonlinear function has learned from data without a fitting procedure.

<Callout title="Finite input does not guarantee representable arithmetic" kind="numerical">
The pure model rejects wrong kinds, empty/ragged/sparse arrays, mismatched shapes, strings, Booleans, NaN and infinity. Each product, running sum and bias addition must remain finite. A nonzero affine product that underflows to zero is rejected. Ordinary rounding and nonzero subnormal products remain possible; rounded sigmoid endpoints are deliberately allowed. The UI is a bounded two-feature explorer with every editable scalar in −1000…1000; the pure model accepts other compatible dimensions. No tolerance changes the model output or excuses overflow.
</Callout>

Exact integer and dyadic worked examples need no approximation tolerance. Independent and unit comparisons check every expected zero exactly. Other nonexact sigmoid values compare to Decimal using relative 32ε plus an absolute 32ε for magnitudes at least 10⁻⁸, where ε=2⁻⁵². Tiny nonzero tails use relative-only comparison. Endpoint cases declared exact use equality; nonexact derived sums, including the sum of separately rounded sigmoid complements near 1, use the allowance rather than an endpoint rule. Browser numerical projections use the stated allowance, including an absolute 32ε at expected zero, independently of these exact oracle/unit assertions. This small-case allowance covers exponential implementation and final rounding; it is not a universal error guarantee or a way to accept a fabricated zero tail. SVG quantities retain full-precision data attributes; labels round for readability.
