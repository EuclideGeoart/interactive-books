## Two sources of variation

A random forest combines bootstrap resampling with random feature subsets at eligible nodes. At each node:

1. Check empty, pure, depth and minimum-count stopping rules.
2. Sample m distinct feature indices without replacement.
3. Enumerate all legal adjacent-value partitions in those features.
4. Choose the greatest positive gain under the deterministic tie rule.
5. Recurse into both children, drawing fresh subsets when they are eligible.

Features are selected by partial Fisher–Yates sampling. With d features, draw a slot among d possibilities for the first index, d−1 for the next, and so on. Sorting the selected indices makes candidate order explicit without changing subset membership. We consume the feature stream in preorder, left child before right.

If m=d, the implementation considers all features and consumes no feature draws. If the chosen subset contains no legal positive-gain candidate, the node becomes a leaf; it does not secretly inspect excluded columns or retry until a favorable feature appears. This is the exact forest policy taught by this sheet.

## How this changes correlation

Suppose a strong predictor would win almost every root search. Plain bagging can then build similar trees despite varying the rows. Restricting each node to a random feature subset gives other predictors a chance to influence branches, potentially reducing correlation between tree errors. Individual trees may also become weaker; the subset size expresses a tradeoff rather than guaranteeing an improvement.

For d=2,m=1, each feature has ideal selection probability 1/2 at an eligible node. This feature choice is separate from its subsequent gain. No selection probability changes the impurity weights: candidate counts still include every bootstrap occurrence at that node.

The output uses the same hard-majority vote and class-zero tie policy as III-23. The source matrix is n by 2; each query is a length-2 row. A bootstrap tree is trained on n draw rows, and every eligible node records its own subset and exact row IDs.

## Stream provenance is an algorithm contract

The master seed reserves a nonoverlapping bootstrap segment followed by a worst-case feature segment for each tree. The feature budget is (2^depth−1)m when $m<d$, otherwise zero. A tree uses only the eligible nodes' prefix of its reservation; unused outputs remain reserved. Thus a pure node's stopping can never shift the next tree into a previous tree's stream.

Changing m can change both feature choices and subsequent bootstrap reservations. Compare policies by the recorded actual seeds and ledgers, rather than assuming that one seed guarantees identical samples across different stream budgets. Setting m=d does reproduce plain bagging because neither policy reserves feature draws.

## Connections and independent checks

The independent oracle derives stream states with closed-form unsigned integer arithmetic, reconstructs the sampled feature slots at each eligible node, and then enumerates all legally separable row subsets to verify the chosen branch. It checks exact seeds, offsets, multiplicities, node features and source IDs; rational voting checks aggregation and OOB exclusion separately.

Trees' individual thresholds are easy to inspect, but a forest's collective behavior depends on many conditional paths. Feature importance or causal interpretation is outside this lesson. III-25 instead uses ordered residual fits: a boosting stage cannot be freely reordered with its predecessor's training target.
