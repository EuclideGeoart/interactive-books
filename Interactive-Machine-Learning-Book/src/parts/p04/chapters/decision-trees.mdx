## A tree partitions input space

A binary classification tree is a collection of conditional tests followed by terminal predictions. At a node containing row set S, feature j and threshold t define

$$
S_L=\{i\in S:x_{ij}\le t\},\qquad S_R=\{i\in S:x_{ij}>t\}.
$$

Equality always goes left. A prediction starts at the root, follows one branch at each test, and returns the terminal majority label. Our binary label tie policy returns class 0. A leaf also stores the fraction of its rows labeled 1; this empirical fraction is distinct from the hard class decision and is not a calibration guarantee.

The batch uses $X\in\mathbb R^{n\times2}$: its rows are samples, its columns are features, and $y\in\mathbb R^{n\times1}$ is the target column. There is no intercept feature or coefficient vector. A single query is a length-2 feature row. Even an empty or pure tree retains this declared shape and rejects missing or extra query entries.

## Enumerate legal partitions

Sort the distinct observed values in each feature. Two adjacent values a and b create one partition represented by threshold (a+b)/2. Duplicate feature values must remain together; we never split identical coordinates just because their labels differ. Both children must contain at least the configured minimum leaf count.

For a node with n rows, let I be its impurity. The candidate score is

$$
\Delta(j,t)=I(S)-\frac{|S_L|}{n}I(S_L)-\frac{|S_R|}{n}I(S_R).
$$

We maximize this reduction, then repeat the same search recursively in each child. Exact computed binary64 gain ties choose the lower zero-based feature index, then the lower threshold. This is a greedy procedure: it finds the best immediate branch among considered candidates, not the globally best tree of every possible shape. The next chapter derives both available classification impurities.

The parent has counts [3,3] and Gini 1/2. At x1 ≤ 2.5, left counts are [2,0], right counts [1,3]. The weighted child Gini is

$$
\frac26(0)+\frac46\left(1-\left(\frac14\right)^2-\left(\frac34\right)^2\right)=\frac14.
$$

Gain is 1/2 − 1/4 = 1/4. This is the selected root test. At x1 ≤ 3.5, both three-row children have Gini 4/9; gain is only 1/18. The latter candidate is legal but worse.

At depth 1, the left leaf predicts 0 and the right predicts 1; s5 is misclassified, so training error is 1/6. Depth 3 separates s5 from s6 and achieves zero error on these six rows. Zero training error provides no evidence about future inputs. Each terminal region is constant, and predictions can change abruptly across its boundary.

## Stop rather than invent a branch

Try **Set pure class 0**, **Set constant features**, and **Use empty data**. Pure labels have zero risk and need no split. Mixed labels with constant features have no separating threshold. Empty nodes carry conventionally zero impurity/risk but an undefined prediction; zero is not fabricated as a label. A depth bound or insufficient rows for two legal leaves also stops growth.

<Callout title="Numeric identity is part of the partition" kind="numerical">
Python normalizes accepted features and targets to detached binary64 values before deduplication, NumPy masks or recursion. Thus integers near 2^53 that round to the same browser value remain together. A midpoint uses a/2 + b/2 to avoid summing large endpoints; if adjacent floats have no representable interior midpoint, threshold a preserves the same ≤ partition. Finite input does not guarantee finite squared arithmetic in regression.
</Callout>

## Connections and verification

Trees express nonlinear decisions through axis-aligned local tests. They do not require smooth derivatives, but small changes in data can change a chosen threshold and its descendants. Depth and leaf limits constrain this sensitivity; III-22 adds regression means and pruning, and III-23 averages separately resampled trees.

The independent oracle enumerates every subset of each tiny node, retains only subsets that a feature can actually separate, and computes exact Fraction Gini scores. This is a different search from sorting adjacent coordinates. It checks exact row membership and literal ties as well as scores. The source table and accessible nested tree retain identities even when plot points overlap.
