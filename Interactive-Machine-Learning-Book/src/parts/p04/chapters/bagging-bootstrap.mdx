## A bootstrap empirical experiment

A bootstrap training sample draws n times with replacement from n source rows. Each draw selects an index uniformly. Its multiplicities (m1,…,mn) sum to n, but some are zero and some exceed one. The multiset feeds the tree learner; replacing it with a set would erase sample weights and change impurity, legal leaf counts and predictions.

For a particular row, the probability of exclusion from a size-n sample is

$$
P(m_i=0)=\left(1-\frac1n\right)^n.
$$

As n grows this approaches exp(−1), about 0.368, under ideal independent uniform draws. This is an expectation over random samples, not a fixed requirement that every small bootstrap sample exclude 36.8% of rows. Our seeded generator produces reproducible pseudorandom draws for inspection.

Bagging fits the same learning procedure separately to these resamples. Each tree may reuse all features at each split. The trees are not trained to correct each other's errors, and no earlier prediction enters a later training target.

## Aggregate the fitted predictions

For binary hard predictions hb(x), the sheet uses

$$
\hat y(x)=\mathbf1\left[\sum_{b=1}^B h_b(x)>B/2\right].
$$

An exact vote tie returns 0. The positive vote fraction is a fraction of hard tree decisions, not the average leaf probability and not automatically a calibrated probability. The canonical kernel also supports scalar-regression bagging, where it averages actual leaf means.

Averaging can reduce variation when tree errors are imperfectly correlated. For equal-variance errors with variance σ² and pairwise correlation ρ, the average has variance

$$
\mathrm{Var}(\bar e)=\sigma^2\left(\rho+\frac{1-\rho}{B}\right).
$$

The identity follows by summing B variance terms and B(B−1) covariance terms, then dividing by B². Increasing B cannot remove the correlated component ρσ². It also does not erase systematic bias or data leakage.

## Derive out-of-bag evaluation

For source row i, let Bi be the trees whose own bootstrap sample excludes that source ID. Its OOB prediction aggregates only those trees. Let E contain rows with at least one eligible nonempty prediction. We report

$$
\mathrm{Acc}_{\mathrm{OOB}}=\frac1{|E|}\sum_{i\in E}
\mathbf1[\hat y_i^{\mathrm{OOB}}=y_i].
$$

This averages eligible source rows once each; rows with more eligible trees do not receive extra evaluation weight. Canonical regression OOB uses mean squared error over the same eligible set.

With the three original trees, s4 has no OOB tree and is excluded from evaluation. The other five rows have OOB predictions [1,0,0,1,0] in order s1,s2,s3,s5,s6. Only s2 is correct, so OOB accuracy is 1/5=0.2. This differs from all-tree training accuracy because every evaluated row is predicted without its own inclusion in the eligible trees.

Try **Keep one source row**. Every nonempty bootstrap includes it, so there is no eligible OOB prediction and the metric is explicitly undefined. **Use empty data** also leaves every query/tree value undefined; it must not fabricate class 0.

## Reproducible streams and limits

The shared LCG uses unsigned 32-bit state. For each tree we reserve n consecutive outputs for bootstrap draws, then a bounded feature-draw segment. Bagging considers all features and needs no feature draws. Tree2 begins after tree1's consumed bootstrap segment, rather than using seeds that create overlapping shifted windows. The visible segment table records offsets and seeds. Uniform pseudorandom resampling is reproducible; the construction is not a proof of statistical independence.

OOB evaluation is useful for bootstrap models but has limited coverage with few trees. It does not replace a held-out test for model selection or distribution change, and source IDs must represent the units that should be excluded together. Grouped or time-dependent observations require different resampling policies.

The independent oracle derives each LCG state by an integer closed form, counts multiplicities with a multiset, enumerates legal splits independently, and aggregates the resulting predictions using exact rational arithmetic. III-24 adds feature randomization at every eligible node, while III-25 changes the training sequence itself.
