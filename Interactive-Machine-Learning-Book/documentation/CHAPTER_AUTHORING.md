`src/curriculum/plan.json` freezes the supplied nine Parts, 41 IDs and titles. A Part publishes its own chapters through `src/parts/pNN/manifest.json`, containing JSON with `part` and `chapters` (each chapter has `id` and `slug`). Add `src/parts/pNN/chapters/<slug>.mdx`. Discovery is automatic; never edit a central availability registry. Registration rejects wrong ownership, duplicate IDs/slugs and missing/renamed/misowned content. Only the integrator accepts and merges publication into main.

Frontmatter requires `chapterId`, the exact plan `title`, a short `hero`, `lede`, `description` (20–300 characters), and `prerequisites` using actual Book II IDs in `src/curriculum/book-ii.json`. `PUBLIC_BOOK_II_BASE` supplies an explicit deployed Book II root (default `/math-foundations/`); unknown IDs fail. The opening interaction comes first. Follow it with intuition, definition, mechanics, derivation, a literal worked example, actual executable Python+NumPy reference code, an explorer, common mistakes, numerical limits, connections, five graded exercises with corrective feedback and a summary. Use `Stage.astro`, `CodeFile.astro`, `Callout.astro` and the shared controls. Code is imported from the actual Part-owned Python file with `?raw`, not copied into a prose fence.

Part-owned models are pure and validate their boundaries. One authoritative state feeds a derived numerical object; plot geometry, formula, inspector, table, trace and accessible description all project that object. Canonical mathematical vectors are columns. Batches store samples in rows of X: n×d features, d×1 weights and n×1 targets. State the intercept, loss normalization, evaluation metric, input provenance and seed separately. Finite input alone does not guarantee finite arithmetic; failures and undefined states carry reasons, not fabricated numbers.

Reuse generic deeply detached immutable traces in `src/platform/trace.ts`; navigating selects a historical state. Editing a replay begins from the displayed state and ends replay. The generic 32-bit LCG in `src/platform/seed.ts` uses `state = (1664525 * state + 1013904223) mod 2^32`, output `state / 2^32`; Python reproduces integer arithmetic. Seeds are unsigned 32-bit integers. Do not claim a seed for hand-authored data.

Canonical code lives in `code/python/pNN/`; independent mathematical oracles in `oracle/pNN/`; golden fixtures in `fixtures/pNN/`; optional source data in `data/pNN/`. Each oracle Part has `manifest.json` with nonempty `selfTests` and `goldenChecks` Python basenames. Self-tests run directly; each golden command accepts `--check` and fails if committed expectations are stale. Golden expectations must derive from a distinct method (analytic/arithmetic/Fraction, finite differences, exhaustive enumeration, robust NumPy linear algebra), not a translation of the browser calculation. State tolerances with a reason and test actual canonical Python execution.

Tests live in `tests/unit/pNN/` and `tests/e2e/pNN/`. Shared publication tests automatically inspect all registered routes, hydration, five exercises, reference code, layouts and both-theme accessibility. Part tests additionally verify genuine mathematical oracles, browser/model parity, physical geometry, invalid/degenerate states, pointer/keyboard/numeric/reset, touch targets and immutable replay. Read the actual package scripts and evidence; do not invent results. Native installed dependencies are a read-only overlay with per-worktree caches; no clone/install/environment replacement.
